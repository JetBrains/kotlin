            7a. break it: a COMPILE error (never reaches the engine)

            7b. break it: a RUNTIME trap in a swapped body
            
fun bump(): Int {
    error("boom")   // compiles fine; traps when CALLED
}

            
expect: the patch swaps in cleanly, then the next bump click traps — the banner shows
            the exception while render and the zoo keep working. The old body is already replaced, so
            the trap repeats until you fix the file.

        

        

            7c. add a method to Model — ACCEPTED (additive; not a shape change)
            
class Model(var count: Int, val label: String) {
    fun reset() { count = 0 }   // non-virtual, in a final class:
}                                // never enters the vtable — no type changes

            
expect: a clean swap. A non-virtual method in a final class doesn't touch the
            vtable, so no wasm type changed — the additive case (Julia semantics: a new method,
            old callers untouched).

        

        

            7d. add an OPEN method to Animal — NOW HOT (vtable migration, live!)
            
// in Animal, after speak():
    open fun pet(): String = "pet"

            
// and use it in intro():
fun intro(): String = name + " says " + speak() + " (" + pet() + ")"

            
expect: a CLEAN SWAP — and the whole zoo chorus instantly gains
            "(pet)", on the SAME instances born at v1. The vtable lives behind the same
            indirection as the payload: adding an open method grows the vtable STRUCT (a new
            type), but the cell's vtable field is root-typed and mutable, so no wasm signature
            changed — and old instances migrate their vtable on the next dispatch (the
            compiler-generated stepper installs the current vtable for the instance's runtime
            class; overrides still win, so the Dog still says woof). This is SBCL's
            wrapper-update, on wasm.


            HOW it works: dispatch lowers to test -> (cast + read slot) | (call the stepper,
            retry); the stepper reads the instance's RTTI klassId, installs the current vtable
            + itable. Old code keeps working on migrated instances for free — a grown vtable is
            a SUBTYPE of the old one.

        

        

            7e. what's still rejected: give Model a CLASS supertype
            
open class Counted { fun kind() = "counted" }

class Model(var count: Int, val label: String) : Counted() {

            
expect: V8 rejects the Model-touching slots at the setters (createModel,
            bumpModel, renderModel…) — the cell SUBTYPING CHAIN is part of every wasm signature
            mentioning Model, so the engine refuses the swapped funcrefs, and the old code keeps
            running. Revert to recover. Gaining an INTERFACE would be additive; a class
            supertype changes the chain (the new Model literally is not the old Model type).
            That's the honest boundary — new instances can be the new type, old code keeps the
            old one (coexistence).
